# KeptWidget v0.4 development / acceptance checklist

**Status:** Work in progress on develop/v0.4. This is not the signed production release.

## First v0.4 milestone
- Offline checkbox queue records its original state and the note's last-updated timestamp.
- Replays are idempotent: if the requested state is already on the server, no second PATCH is sent.
- Changed notes are held for review instead of overwriting potentially newer server edits.
- Legacy queued checkbox actions lacking a baseline are not blindly replayed.
- HTTP 408, 425, 429 and 5xx are retried rather than mislabeled permanent conflicts.
- Sync drains newly appended work in bounded passes with fewer widget refreshes.
- Single-note widget groups unfinished entries first; completed entries are collapsed with a full count and expand/collapse action.
- New Robolectric tests cover replay, timestamp checks, retry handling and completed-group selection.

## On-device acceptance test plan

1. **Signing:** Keep signed v0.3 installed. Do not install an unrelated debug-signed PR artifact on top of it.
2. **Single-note widget:** Select a checklist with completed items. Verify the completed count, expand/collapse action, correct dark-mode styling and scroll behavior.
3. **Checklist mutation:** Tap unchecked and completed entries; verify each reaches the intended server state exactly once.
4. **Offline:** Open a note online to cache its contents. Disable connectivity, toggle a checkbox, restore connectivity and verify the queued action syncs.
5. **Lost response:** If the server accepted a request but the response was lost, subsequent replay must not toggle it again.
6. **Concurrent edit:** Change a note on device B while a checkbox mutation is pending offline on A; A must not overwrite the newer note.
7. **HTTP errors:** 429 and 503 remain queued; deleted checklist items are conflicts.
8. **UI regression:** Original note line breaks, colorful cards, dark theme, opacity settings and grid/list widget filters still work on the Galaxy Fold outer and inner displays.

## Remaining work before a production v0.4
- Native reminder notifications and recurring schedules.
- Authenticated photo/media previews with caching and privacy checks.
- Integration tests against a disposable Kept server, plus on-device testing.
- Performance and widget refresh improvements under large note collections.

**Known limitation:** Kept reports noteRevisions=false and idempotentMutations=false. The client can check for stale changes before PATCH, but cannot guarantee atomic server-side conflict protection.
